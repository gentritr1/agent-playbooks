### Rulings
- **R43 · EXPO-004's "not go native" and the Skia shader win are one rule.** arrows-game measured that "native" was not the cure (an oversized native display list ran 125.6 ms p95, worse than Skia's 18.78 ms) and that the cure was the owner and the boundary traffic: a bounded, retained view fed geometry once and a mask per exit (11.45 ms). geoguesser's shader won for the same reason: per frame it receives two floats, where the SVG arm regenerated and re-parsed ~46 KB of geometry. So: ownership first; static geometry gets a retained, bounded owner; when the per-frame work is reprojection of geometry (every pixel moves each frame), the owner is a GPU shader fed uniforms. Skia is chosen because of what crosses the boundary per frame, not because it is native, and a static board still prefers a retained owner over a Skia redraw (arrows-game's 18.78 vs 11.45 ms).
- **R44 · One new skill, named `rn-render-perf`, not `rn-gpu-motion`.** The GPU rules alone did not fit `expo-rn-apps` (body 1,360 of 1,500 before; five rules add ~1,100), and EXPO-004 is the dense-rendering rule they extend, so it moved with them (ids are not tied to skills, R12). ## 0.3.0 · 2026-10-07

Lessons from the LOMN web port (a C++17 port of a 2001 PC game to native arm64 and wasm32 WebGPU, players bring their own game files), and a detection gap in `check-applicability.py`. Sources: lomn-web `docs/knowledge/measurements.md`, `docs/knowledge/audits/2026-10-07-m1a1-parser-security.md` and `2026-10-07-m1a3-osi-textures-parser-security.md`, `docs/knowledge/web-porting-playbook.md`, the SDD ledgers `.superpowers/sdd/2026-10-07-lomn-web-m1a3/progress.md`, `.superpowers/sdd/2026-10-07-lomn-web-m1a4/progress.md` and `task-4-review.md`, commits `74a5a69`, `2856ce9`, `bb49736`, and lomn-web project memory.

- **`ctx:web` detection.** It was detected only from `next`, `vite`, `react-dom` or `astro` in the root `package.json`, so lomn-web (root Makefile with Emscripten, `web/index.html`, `web/package.json` with Playwright) and plain static sites read "ctx:web not detected" and UI-007 was UNKNOWN. Now also: an `index.html` at the root or in `web/` or `public/`, or a `web/package.json` declaring a web framework or Playwright. Root-only, never recursive. lomn-web before → after: `UI-007 UNKNOWN [heuristic] ctx:web not detected` → `UI-007 APPLIES [heuristic] ctx:web detected`; VERC-001..005 stay UNKNOWN on `ctx:vercel` (no Vercel config there); summary APPLIES 29 → 30, UNKNOWN 30 → 29.
- **New `ctx:wasm`**: an Emscripten reference (`emcc`, `em++`, `emcmake`, `emmake`, `emsdk`, `EMSCRIPTEN`) in the root Makefile or CMakeLists.txt. PORT-005 needs it.
- **Versions from `web/`**: a package absent from the root is read from `web/node_modules`, then the `web/package.json` range, so PORT-004's `playwright@1.63` resolves on lomn-web (installed 1.63.0).
- **Tests** (`ContextDetectionTests`, 10 cases): 6 positive fixtures and 3 negative controls (an RN app; a pure Android app with a WebView `assets/index.html` and an NDK CMakeLists below the root; a Python lib with a Makefile and built HTML docs).
